### 5.2 但 §4.4 的 SRC-02 **今天就是坏的**

`V06Effects2.RevokeEquipment` / `RevokeSeal` 用一个无条件的 `RemoveKw`：

```csharp
case "Q06": u.RemoveKw("坚壁"); break;
case "Q03": u.RemoveKw("远射"); break;
case "Q08": u.RemoveKw("汲取"); break;
case "Q09": u.RemoveKw("协攻"); break;
case "Q11": u.RemoveKw("飞行"); break;
// RevokeSeal:
case "A01": u.RemoveKw("护卫"); break;
case "A02": u.RemoveKw("再生"); break;
case "A04": u.RemoveKw("余烬"); break;
case "A05": u.RemoveKw("夜行"); break;
```

而 `V06Unit.AddKw` 是 `if (!Has(kw)) Keywords.Add(kw);`——**单位本来就有该关键词时，装备/附印不会新增一条，撤销时却会删掉本体那一条**。

| `Q03` 游侠符镜 | 远射 | `U-E01` 白枝游侠 | 卸下后**永久失去远射** |
| `Q08` 绯月细剑 | 汲取 | `U-V02` 暮色剑士 | 卸下后**永久失去汲取** |
| `Q09` 部族战旗 | 协攻 | `U-G01` 哥布林巫祝 / `G05` / `T03` | 卸下后**永久失去协攻** |

## 七、§6 AI 三档难度

### 7.1 当前 AI 的真实能力

| 项 | 现状（`V06Ai`） |
| --- | --- |
| 搜索深度 | **D1**：对每个候选动作 `Clone()` 后 apply，再 `ScoreAfter` |
| 响应窗口处理 | 对防守方的合法动作取**最坏值**（＝文档"最优防守假设"），且**已排除 `Respond`**（隐藏信息隔离，上一轮修过） |
| 根层候选 | 全枚举，无上限 |
| 节点预算 | 无 |
| 随机扰动 | `NextRand() % 7 - 3`（±3，固定，不区分胜负极端） |
| 信息样本 | 无（1 个样本；搜索直接跑在真实引擎克隆上） |
| 难度档 | 无，只有一档 |
| `Eval` 读敌方信息 | 只读 `b.Hand.Count`（公开的张数）✅ 不读身份 |
| 确定性 | `Seed()` + 自建 `Rand` 链 ✅ |

### 7.2 结论：这份 §6 的第一个动作不能是"加深深度"

因为 `LegalActions()` 是从**真实引擎状态**枚举的。现在只在攻击响应窗口用它，而响应阶段的合法动作里唯一的隐藏信息是 `Respond`（已被排除），所以暂时安全。

**一旦按 §6.1 把 D2 展开到"对手下一次主行动"**，`LegalActions()` 就会用对手**真实手牌**枚举部署 → AI-01（隐藏手牌不影响决策）与 AI-03（最优防守不越权）**立刻失败**。

所以顺序必须是：

1. 先做 **可见观察 → 信息样本**：从观察重建 `V06Player` 的未知部分（手牌按模式先验抽样、牌库按剩余数量重排），搜索只跑在样本上，样本用独立随机流
2. 再加深 D1/D2/D3 与节点预算
3. 最后才调扰动与评分区间

另外 §6.2 把"简单／标准"的防守假设设得比 B0 弱、`困难`更强，但 B0 已经是"最坏防守"——所以 `标准 vs B0 = 45–60%` 这条**不能先验假定会成立**，要用 128 局冒烟先测一次单调性。

### 7.3 需要新建的验收设施

- 1600 局／档的镜像配对跑批（现值 `V06BatchRunner` 只跑检查，没有批量对局报告器）
- p95 单次决策计时（≤50/150/400ms）
- 「已完成轮数」统计必须按"结算完成的轮数"，不能直接用 `Round`（文档这点写对了：引擎第 12 轮 `Judge()` 前会把 `Round` 加到 13）
- AI-01～AI-07 七条可判定用例
