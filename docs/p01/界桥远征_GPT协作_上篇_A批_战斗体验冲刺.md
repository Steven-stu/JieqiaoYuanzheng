## 2. 硬约束（违反其中任一条，改动会被直接回退）

1. **不许改规则**：`Assets/Scripts/Core/**` 一个字都不改（B 批也一样）。你只能改 `Assets/Scripts/UI/**` 与新增 UI 侧文件。
2. **不许加依赖**：禁止 TextMeshPro、DOTween、Addressables、任何 NuGet/UPM 新包。只用 `UnityEngine` / `UnityEngine.UI` / `UnityEngine.EventSystems` / `System.*`。
3. **不许用 Prefab / 场景资源 / 图片**：界面全部代码构建（这是本项目既定风格）。要图标就用文字、几何图形（`UiKit` 里的 Panel）或现有 Sprite 名。
4. **语法上限 C# 8**：别用 `record`、`init`、顶层语句、`file` 作用域类型。可以用 `switch` 表达式、`using` 声明。
5. **保持公开 API**：`V06BattleUI` 现有的 public 成员（`Engine`、`CurrentActions`、`ClickAction`、`ClickReserve`、`ClickRespondByIndex`、`StartMatchDeck`、`ForceRefresh`、`IsResponding`、`ResultPanelVisible`、`ScreenFxCount`、`SwapConfirmVisible`、`PendingTactic`、`ClickSwapConfirm` 等）**签名不许变**，自动化巡检依赖它们。可以新增 public 成员。
6. **文字用中文，术语必须与 `V06Terms.cs` 一致**：术语表里每条都是按现有引擎实现写的，你的提示文案不许与它冲突（例如「远射」「坚壁」「汲取」的解释）。
7. **不要碰音频**：音效槽位是固定 42 个，本批不涉及。
8. **安全第一**：任何新逻辑都要能在「引擎为 null / 对局已结束 / 对手回合 / 响应窗口」这四种状态下安全返回，不许抛异常（现有代码里 `Update()` 每帧都在跑）。

## 3. 设计基线（改 UI 必须守的数字）

- 设计分辨率 **1600×900**，根节点按 `min(w/1600, h/900)` 缩放；所有坐标写死在这个空间里。
- 战斗棋盘格位：**112×149**，手牌 **112×149**，预备区 **84×112**。
- 格位横坐标 `618 + 126*col`，两排纵坐标 `44`（敌前排）/ `196`（敌后排）/ `395`（我方前排）/ `547`（我方后排）。
- 手牌起点 `(737, 24)`，间距 122；旗血数字在 `y=699` 附近。
- 右列功能按钮 **336×44**，纵向排在 `y=226…466`。
- 卡面文字三行带：卡名 14px / 关键词 11px / 数值 16px。**不要把 112 宽的格位塞满长句**。
- 颜色一律走 `UiKit` 的常量（`UiKit.MyCamp`、`UiKit.FoeCamp`、`UiKit.Selected`、`UiKit.TextMain`、`UiKit.TextDim`、`UiKit.ButtonNormal` 等），不要自己 new Color。

## 4. A 批任务清单（6 项，按优先级）

### A1 ★★★ 无效操作统一反馈（最高优先，改动最小、感知最强）

**现状问题（真实玩家反馈）**：点不该点的地方**完全没反应**，玩家不知道是自己点错了还是程序卡了。

**要求**：
1. 抽出统一入口（建议 `private bool RejectAction(string reason, GameObject target = null)`）：
   - 在**顶部提示带**（现有 `_hint` 机制，`y≈348/372` 那条）显示 `reason`，持续 3 秒；
   - 若给了 `target`，让该控件**红闪 150ms**（`UiKit` 里用协程改 `Image.color`，结束后恢复原色，重复点击要能重置计时，不要叠加协程泄漏）；
   - 同时播放**已有**的「无效」音效槽（查 `V06Audio` 现有方法名，别新造）。
2. 把现有所有「静默 return」改走这个入口，至少覆盖：
   - 点空格部署但牌不能部署；点敌方空格；点自己满格位；
   - 行动点不足 / 主行动用尽 / 该单位本轮已攻击 / 被护卫挡 / 射程不够；
   - 响应窗口内点主行动按钮；对手回合点任何东西；
   - 换位模式下点同排格子（提示「要选它对面那一排的空格」）；
   - 战术需要落点却点了非法格（保持现有两段式语义，只加反馈）。
3. **文案要求**：每条 reasons ≤ 18 字，且必须说「为什么 + 怎么办」。
   例：`行动点不够（还需 2 点），先点『让过』结束本轮`、`该单位本轮已攻击，换一只试试`、`被护卫挡住：先打带护卫的单位`。
4. 不许用「操作无效」「不能这样做」这类无信息量的话。

**验收标准**：
- 12 种非法点击，每一种都能看到「顶部文字 + 目标红闪」；
- 连续快速点同一个非法目标 5 次，红闪不叠加、不残留（最后颜色必须恢复原色）；
- 战斗中正常操作不受影响（现有 `ClickAction` 路径仍然 0 失败）。

---

### A2 ★★★ 行动可行性徽标（让玩家一眼看出「这张现在能不能打」）

**现状问题**：手牌/预备/场上单位看不出可用性，全靠试。

**要求**：
1. 手牌卡面右上角（或在费用徽标旁）加一个**状态角标**，四态：
   - `可打出`（绿）：费用够 + 主行动还有 + 目标存在；
   - `费用不足`（灰）：显示还差几点（如 `差2`）；
   - `本轮已满`（灰）：主行动用尽；
   - `无目标`（灰）：费用够但没有合法目标（例如治疗牌但全场满血、换位牌但对面没空格）。
   不可打出的牌**整体压暗到 55% 不透明度**（`CanvasGroup.alpha` 或 Image 颜色），但仍可点击（点了走 A1 的说明，而不是禁用点击——禁用会让玩家不知道原因）。
2. 预备区同样处理（预备还有「本局已用过」这一态）。
3. 场上单位：在**本单位脚下**加一行 10px 小字状态，只显示最要紧的一条（优先级：`已攻击` > `已部署` > `可攻击：N`），可攻击数量为 0 时就写原因（`射程不够` / `被护卫挡`）。
4. 所有判断**必须调用现有引擎查询**（`Engine.AttackTargets(u)`、`EnumeratePlays`/`CurrentActions`、`MainActionsLeft`、`ActionPoints`），**不许自己重算规则**，避免与引擎口径不一致。可以每帧缓存一次（`Refresh()` 里算好，别在 `Update()` 里反复遍历）。

**验收标准**：
- 费用不足时手牌压暗 + 角标显示差额；让它变够用（让过后 AP 回复）后自动恢复明亮；
- 场上单位打完一次后立刻显示 `已攻击`；
- 棋盘 12 格 + 手牌 9 张 + 预备 6 张的刷新开销 < 1ms（不要每帧重建控件，只改文字/颜色）。

### A3 ★★ 战斗内一次性引导（新玩家第一个 30 秒）

**现状问题**：新玩家不知道「4 点主行动 / 换位免费 / 让过」这些核心规则，第一局基本在乱点。

**要求**：
1. 纯代码的**分步指引覆盖层**（不要美术、不要遮罩全屏截图）：
   - 半透明黑底（alpha 0.55）+ 一块 520×260 面板 + 「第 N/6 步」+ 说明 + `下一步` / `跳过引导`；
   - 每步**只讲一件事**，并**高亮对应控件**（在目标控件外画 2px 描边矩形，用 `UiKit.Panel` 拼，别用 shader）；
   - 6 步内容建议：
     1. 「这里是你的手牌：点一张牌，再点亮起的格子就能部署。」
     2. 「每轮只有 4 次主行动，用完后点『让过』交回合。」
     3. 「『换位』不花行动点、每轮 1 次，但要先点单位再点目标格并确认。」
     4. 「后排单位要打人需要『远射』或『飞行』；被『护卫』挡住的敌人要先清护卫。」
     5. 「点敌兵就是攻击，本轮攻击过的单位脚下会写『已攻击』。」
     6. 「左上角是你的远征旗，归零就输；第 8 轮起双方每轮都掉旗血，别拖太久。」
2. 触发条件：**只在玩家第一次进入战斗时弹**（存档里记一个 `tutorialBattleDone`；`V06Save` 已有存档结构，加字段要**向后兼容**：缺字段就当未看过）。
3. 引导期间**不阻断**对局（对手 AI 照常走，但引导面板不遮棋盘、不吞点击，除非玩家点「下一步」）；
4. 「跳过引导」= 直接标记完成，本局不再出现；
5. 设置里（或按住 `F1`）可以重新看一遍。

**验收标准**：
- 新存档第一次进战斗必现；看过/跳过后再进不再出现；
- 引导期间点棋盘仍能正常部署/攻击；
- 中途退出战斗再进，进度不丢（不会从第 1 步重来）。

### A4 ★★ 结算面板增强（结束得好不好，决定还玩不玩下一局）

**现状问题**：结算只有胜负 + 回大厅，缺「这局我打得怎么样」和「马上再来一局」。

**要求**：
1. 结算面板补 5 个数据（都能从 `Engine` 现有字段/日志算出来，不许改引擎：
   - 回合数、我方/敌方旗血余量；
   - 我方累计造成的单位伤害（可从 `Engine.Log` 或 `V06BattleFx` 已采集的飘字累计，取一种口径并在代码注释里写明）；
   - 击杀数（敌单位阵亡数）；
   - 本局最高单次攻击；
   - 使用的战术牌数。
2. 三个按钮：`再来一局`（同卡组同座位，换种子）、`换卡组再来`（回组卡页）、`回大厅`。
3. 失败时给**一句具体建议**（按数据挑一条，不要泛泛的「再接再厉」）：
   - 旗血先归零且主行动用尽次数多 → 「你每轮常把行动用光，试试留 1 点做响应」；
   - 单位阵亡多 → 「前排别空着：有护卫的单位放前排能挡住直攻」；
   - 8 轮之后被压死 → 「第 8 轮起每轮掉旗血，收尾别拖」。
4. 结算演出**必须只播一次**（现有 `_resultShown` 守卫 + `PlayScreenOnce` 去重机制要沿用；上一版出现过「白色卡死」就是每帧重放导致的）。

**验收标准**：
- 手动结束一局（把敌旗打到 0）→ 面板出现，5 项数据非零且合理；
- 连点任意按钮不会重复播放演出 / 不会出现全屏白层堆积（`ScreenFxCount ≤ 1`）；
- 「再来一局」能直接开新局且卡组与座位不变。

### A5 ★ 键盘快捷键（老玩家效率）

| 键 | 行为 |
|---|---|
| `Esc` | 取消当前选择（手牌/单位/预备/落点等待/换位确认框） |
| `空格` | 让过（我方回合且无响应窗口时） |
| `1–9` | 选中第 N 张手牌（再按一次 = 执行无目标牌） |
| `Tab` | 在「我方单位」间循环选中 |
| `F1` | 重看引导 |
| `Enter` | 确认当前弹窗（换位确认 = 确定） |

要求：只在战斗界面激活且没有输入框焦点时生效；不要拦截系统的 `Alt+F4`、`Ctrl+C` 之类。
**验收**：6 个键逐个按一遍，行为与上表一致；输入法/大写锁定下也不错乱。

### A6 ★ 攻击/结果预览（把「我猜」变成「我知道」）

**要求**：选中我方单位后，在**可攻击目标**上显示一行 10px 预览文字：
- `命中 3`（实际伤害，已扣掉目标「坚壁」）；
- 若目标有护卫/潜行导致不可选，则显示不可选原因（`被护卫挡` / `潜行不可点`）；
- 若本次攻击会触发「汲取/龙威/余烬」等关键词，预览后追加一个短标记（如 `命中3·汲取`）。
数值**必须复用引擎计算路径**：如果 `V06Engine` 里有 `PreviewAttackDamage(...)` 之类方法就用它；没有就**只读**用同样公式在 UI 侧算一份，并在注释里写明「与 V06Engine.ModifyAttackDamage 同口径，改动需同步」。

**验收**：3 种情况（普通命中 / 目标有坚壁 / 被护卫挡）预览数字与实际结算数值一致。
