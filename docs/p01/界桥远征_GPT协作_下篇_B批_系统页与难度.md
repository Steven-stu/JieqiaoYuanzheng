## 3. B 批任务清单（6 项，按优先级）

### B1 ★★★ 商店：事务顺序 + 状态三态（最容易被玩家骂的地方）

**现状风险**：购买流程存在「先发货后扣款 / 扣款失败但货已给」的顺序隐患；已购状态、余额不足、库存上限都没在界面上说清楚。

**要求**：
1. **事务顺序改成「先校验 → 再扣款 → 才发货 → 失败回滚」**，任一步失败都不得留下部分状态（扣了钱没货 / 有货没扣钱）。所有改动集中在一个 `TryPurchase(itemId, out string error)` 里，界面只调它。
2. 每个商品卡显示**四态**角标：
   - `可购买`（绿）；
   - `余额不足`（灰 + 差多少：`差 120 币`）；
   - `已达上限`（灰，限购类商品）；
   - `已售罄 / 今日已买`（灰）。
3. 点不可购买的商品 → 走 A 批 A1 的统一反馈（顶部提示 + 目标红闪），**不要弹模态框**。
4. 购买成功后：货币数字滚动到新值 + 顶部提示 `已购买【名称】，剩余 X 币`；购买失败：提示具体原因（不许只写「购买失败」）。
5. 商店页加一行「本日已/可买」计数（如 `今日 2/3 次`），刷新时间口径要与现有签到/商店逻辑一致（按本地日期）。

**验收**：
- 余额不足点 3 次：3 次都是提示 + 红闪，且货币不变；
- 正常购买 1 次：货币 -价格、商品库存 -1、提示正确；
- 故意让发货失败（例如把库存改成 0 后购买）：货币必须**不扣**；
- 关掉游戏重进：购买状态与货币一致（存盘正确）。

### B2 ★★ 图鉴：能不能用一眼可见（含未实装标注）

**要求**：
1. 图鉴卡池现在是 **332 张**（192 基础 + 140 扩展：兽群 B44 / 少女 G16 / N 系列 N61–N140 共 80）。分页与筛选必须覆盖全部 332 张，**不许出现「第 1 页正常、最后一页空白」**。
2. 每张卡角标标注状态：
   - `已拥有`（有 N 张副本时显示数量）；
   - `未解锁`（灰色 + 锁形文字 `锁`）；
   - `未实装`（**只有确实没有效果实现的卡才标**，判定标准：`V06Effects.EnterSpec`/`V06Effects2` 里没有对应分支，且卡面文字不是「无。」/纯关键词。若拿不准，一律按「已实装」，不要误标）。
3. 顶部筛选条：`阵营（全部/人类/精灵/矮人/血族/兽群/龙族/构装/兽人…）`、`类型（单位/战术/装备/附印/战况/响应/晋阶/支援/衍生物/遭遇/事件）`、`费用 1–4`、`关键词多选（21 个真实关键词）`、`只看已拥有`。筛选状态在返回图鉴时要保留。
4. 搜索框支持卡名与卡号（`N61`、`U-H01` 都能搜到）。
5. 详情弹层补两项：`关键词解释`（读 `V06Terms`，已有 hover 可复用）与 `这张卡能进哪些预组`。

**验收**：
- 332 张逐页翻完无空白页、无重复、无遗漏（可用 `只看已拥有` 对照）；
- 4 组筛选组合切换后计数正确；
- 搜「N61」「绯樱」都能定位到同一张卡。

### B3 ★★★ 组卡：合法性实时校验 + 一键修卡

**要求**：
1. 当前卡组**实时**显示三条硬指标，任一不满足就红色高亮并给一句话原因：
   - 主牌 24 张（现在是 `单位×2 + 战术×2`）；
   - 同名 ≤ 2 张；
   - 阵营/预组限制（若有）。
2. 顶部一行摘要：`单位 X / 战术 Y / 总计 Z（需 24）`、`平均费用`、`低费(≤3)单位数`。
3. 三个一键按钮：
   - `一键补满`（用当前卡组的同名规则自动补到 24，**只加不删**）；
   - `清空`（二次确认）；
   - `改用推荐卡组`（从 `V06DeckLibrary` 的 13 套预组里挑同阵营那套）。
4. 卡组名双击改名（已有）；补 `删除卡组`（二次确认，**不能删最后一组**）。
5. 右侧卡片池支持「点击加入（+1）/右键减少（−1）」，并在卡上加 `×N` 数量角标；已达上限（同名 2）时角标变红且点击给提示。
6. **不合法卡组不许开局**：开局按钮置灰 + 悬停说明缺什么（不要只在点下去之后弹错）。

**验收**：
- 把某张卡加到 3 张：立刻变红 + 提示「同名最多 2 张」，开局按钮置灰；
- `一键补满` 后 24/24 且同名不超限；
- 删卡组到只剩 1 组时，删除按钮置灰。

### B4 ★★ 签到 / 个人资料：让「回来玩」有回报感

**要求**：
1. 签到页显示**连续天数**（当前连续 / 最长连续）与「明天再来得 X 币」，签到后数字即时更新。
2. 断签要有明确文案（`昨天没来，连续已重置为 1 天`），不要静默清零。
3. 个人资料页补战绩统计：总对局、胜/负/平、胜率、最长连胜、最常用卡组、累计击杀。数据来源只用现有存档字段或本批新增的持久字段（**向后兼容**）。
4. 结算时（A 批 A4 面板）把「本局战绩已计入」写清，避免玩家怀疑没保存。

**验收**：签到 → 关闭游戏 → 重进，连续天数与货币一致；打一局后胜负数 +1。

### B5 ★★★ AI 三档难度（战斗之外唯一能让「老手不退坑」的改动）

**允许改的唯一引擎文件**：`Assets/Scripts/Core/V06Ai.cs`（在仓库是 `source/scripts/pNN/Core/V06Ai.cs`）。

**要求**：
1. 加 `V06AiDifficulty { 新手, 标准, 挑战 }`，默认 `标准`，存放在 `V06SaveData`（向后兼容加字段），在**大厅/开局页**可切换（新手=「轻松」，挑战=「硬核」）。
2. 三档差异**只能体现在决策质量**，不许给 AI 开挂（不许改数值、不许额外抽牌/加费）：
   - `新手`：只考虑前 60% 候选动作；有 35% 概率选次优解；不做「留 1 点响应」这类计划性动作；
   - `标准`：现有行为（**保持现状，回归测试基准就是它**）；
   - `挑战`：候选动作全量评估 + 额外一层「对手下轮最可能反击」的简易前瞻（只用现有引擎枚举，不许自己实现新规则）；优先用满 4 次主行动；有响应牌时优先留 1 点 AP。
3. **确定性**：同种子 + 同难度 → 同结果（现有局域网锁步依赖这个；难度必须进种子派生里）。
4. 结算面板显示本局难度；连胜 3 局以上时提示「可以试试硬核」。

**验收**：
- 同种子同难度跑 10 局，结果完全一致（现有 `不变量自检` 覆盖）；
- 新手档胜率明显低于标准档（各跑 20 局对比，写进你的回答里）；
- 标准档行为与改动前一致（这是硬性回归要求）。
